# Navmesh glossary and cell borders

## Glossary

| Term | Meaning in this project |
| --- | --- |
| **CELL / working cell** | A Skyrim area. For a single-cell run, the working cell is the area whose walkable geometry you regenerate. An exterior cell shares boundaries with neighboring cells. |
| **NAVM** | A plugin record containing a navmesh: vertices, triangles, and navigation connections. A cell can contain several NAVM records. |
| **Authored NAVM** | An existing NAVM read from the active plugins, whether made by Bethesda or a mod author. It means existing navigation used as input, rather than navigation generated by this tool. |
| **Winning record** | The version of a record that takes effect after applying the load order. The tool matches borders against this version of the neighboring NAVM. |
| **Candidate** | Generated walkable triangles before they are written into a plugin. Candidate JSON, OBJ, and the scene preview show this geometry. |
| **Primary NAVM** | The existing NAVM in the working cell chosen to hold generated geometry. The writer chooses the one with the most existing triangles. This is a writer convention, rather than a separate Skyrim record type. |
| **Secondary NAVM** | Any other existing NAVM in that same working cell. The writer keeps its identity but writes empty geometry because generated geometry is stored in the primary NAVM. These are not neighboring cells' NAVMs. |
| **Primary and secondary triangle spaces** | The separate lists of triangle numbers belonging to the primary and secondary NAVMs. Here, “space” means a numbering system, not a coordinate system. A link names a NAVM identity and a triangle number inside it. After generation, a triangle with the same number can be elsewhere; an emptied secondary NAVM has no triangles left to target. |
| **Border edge** | A side of a triangle at a cell boundary. Both endpoints, including height, must line up with the neighboring edge. Nearby individual vertices are insufficient if they form different edge segments. |
| **Portal / external link** | A saved connection from an edge in one NAVM to a triangle in another. At a cell border it is the crossing represented by the Creation Kit's green border bar; it is not a physical doorway. The format also has separate door connections. |
| **Reciprocal links** | The two directions of a connection: the working edge points to the neighboring triangle, and the neighboring edge points back to the generated triangle. |
| **Stitching / border alignment** | Reshaping and dividing the generated boundary to match existing neighboring edges, then recording connections. Only the candidate's geometry is changed. |
| **Override** | A record in the output plugin that replaces an existing record when loaded after it. Source plugins are not edited on disk. A neighboring override can preserve its vertices and triangles while updating its connections. |
| **Open / unmatched border** | An edge with no saved connection to the neighboring navmesh. It can reach the cell boundary without allowing an NPC to cross there. |
| **NAVI / XNDP** | Other navigation information: NAVI is a navigation information map; XNDP stores a door reference's navigation association. The exporter does not rebuild these. NAVM border checks do not validate them. |

## What the Creation Kit's green border bar means

Your expectation is correct: the two sides need matching border edges. A mesh
reaching the nominal cell boundary is insufficient. Finalizing in the Creation
Kit records the connection when it can match the edges; the green bar indicates
a link, rather than merely two nearby vertices.

The generator follows that geometric requirement. It reads neighboring navmeshes,
merges compatible collinear subdivisions in the generated boundary, and divides
generated edges where the neighbor has endpoints. Small inward offsets trim the
generated boundary; outward offsets use bounded extensions. Successful matches
use the neighbor's exact endpoints, including height. Distance, step, slope,
and topology checks can reject a match. Applicable tolerances are defined by
the navigation profile and shared border policy, rather than by this guide.

Missing support, different heights, disconnected gaps, or incompatible boundary
layouts can prevent a match. Unmatched generated seam wedges retract into the
working cell, and components without a real portal or matched door are removed.
Every remaining generated CELL seam must consume an exact neighboring edge.
Inspect `border_links` and topology findings in candidate JSON for these checks.

## Why a single-cell export can include neighboring NAVMs

The working cell's vertices and triangles are regenerated. Neighboring vertices
and triangles stay as they were. However, their saved links can refer to triangle
numbers that no longer mean the same thing in the working cell.

For example, a neighboring edge may point to a triangle in a secondary NAVM
that the writer empties. Keeping that link would leave a nonexistent destination.
A link into the primary NAVM can also point to the wrong triangle after
regeneration. The writer therefore removes incoming links into replaced NAVMs
and writes new return links for matched borders. Unmatched incoming edges become
open boundaries. Connections to unrelated NAVMs are retained.

This requires neighboring NAVM overrides containing connection-table changes.
Keeping all neighboring records unchanged would require preserving the old
triangle identities and connections in the working cell, which this full
regeneration path does not do. Neighboring geometry and source files are preserved.

## What the checks establish

Automated checks verify exact endpoint alignment for supported matches, valid
triangles and indices, reciprocal links, and preserved neighboring geometry.
The exporter reads its written NAVMs back before reporting success. These checks
do not establish that the Creation Kit displays a green bar or that NPC
pathfinding works in game. NAVI and door-reference information remain outside
the exporter's rebuild scope. See the [format study](navm-format-study.md) for
limitations and the [candidate algorithm](candidate-surface-algorithm.md) for
stitching details.
